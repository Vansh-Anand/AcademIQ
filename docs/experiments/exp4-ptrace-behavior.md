# EXP-4: Privilege Escalation / Ptrace-Like Process Manipulation Detection

## 1. Objective
Validate AcademIQ's Layer 3 (L3) simulated eBPF security telemetry pipeline. The experiment demonstrates the system's ability to ingest kernel-level `SyscallEvents` via ringbuffer simulation, correlate them to registered agent identities using `cgroup_id` constraints, and correctly classify/block unauthorized process manipulation attempts (e.g., `ptrace`) originating from monitored scopes while safely ignoring unrelated system events.

## 2. Threat Model
Attackers attempting privilege escalation, container escapes, or credential dumping (e.g., extracting SSH keys or database secrets from memory) frequently rely on process injection techniques leveraging the `ptrace` syscall or similar debugging interfaces. If an automated AI agent falls under adversarial control (via prompt injection or hijacked API returns), the adversary may execute obfuscated payloads designed to attach debuggers to other processes on the host. Traditional allowlists may miss this if the agent uses standard built-in debug tools. AcademIQ's L3 engine acts as the lowest-level execution firewall.

## 3. Safe Simulation Boundary
To avoid executing real destructive kernel exploits:
- **No real privilege escalation was attempted.**
- **No real processes were attached to.**
- The environment uses **SimulatedL3Collector**, which plays back synthetic eBPF traces (`tests/fixtures/telemetry/exp4_ptrace_attempt.jsonl`) mimicking kernel ring buffer structures.
- Events follow the standard AcademIQ `SyscallEvent` schema, mapping closely to actual `bpf_core_read` telemetry generated by the native Phase 1B L3 implementation.

## 4. Existing Components Reused
This experiment exclusively leverages existing infrastructure:
- `SimulatedL3Collector`: Reads JSONL traces and simulates eBPF ring buffer dispatch.
- `AgentScopeManager`: Enforces least-privilege identity constraint maps between `agent_id` and linux `cgroup_id`.
- `ExecutionCorrelationManager`: Processes telemetry against allowed network/execution states, updated in this experiment to actively intercept and flag `ptrace` as unauthorized manipulation.
- `ExperimentHarness` & `AcademiqOrchestrator`: End-to-end event processing lifecycle.

## 5. Telemetry Architecture
L3 Telemetry is processed as follows:
1. `SimulatedL3Collector` parses raw JSONL trace events.
2. The `cgroup_id` of the event is queried against the `AgentScopeManager`.
3. If the cgroup belongs to a registered AI agent (e.g., `cgroup_id=1000` mapping to `test_agent_1`), the event is tagged with the agent's identity and dispatched. If it is unmonitored (`cgroup_id=9999`), it is gracefully dropped (protecting host privacy and minimizing overhead).
4. The event routes to the `ExecutionCorrelationManager` which evaluates syscall behaviors (e.g., ensuring `execve` has pending L2 authorization, or trapping `ptrace`).

## 6. Baseline Methodology
The Naive Baseline Monitor represents a standard unstructured string filter:
- Evaluates every trace event independently.
- Contains a simplistic rule: `if syscall == "ptrace" -> BLOCK`.
- Crucially lacks namespace/scoping awareness (no cgroup attribution).

## 7. AcademIQ Methodology
The AcademIQ Pipeline:
- Loads exactly the same telemetry via `SimulatedL3Collector`.
- Silently ignores unmonitored system events without dispatching them to the correlation engine.
- Translates `cgroup_id` -> `agent_id`.
- Emits an `UnexpectedExecutionEvent` specifically tracking the agent identity when an unauthorized scoped `ptrace` is observed.

## 8. Scenario Definitions
The simulated trace contains six events representing three logical flows:

1. **Scenario A (Benign Scoped Activity)**: 
   - `execve` -> `openat` executed by `cgroup_id=1000`. 
   - *Expected:* ALLOW.
2. **Scenario B (Suspicious Scoped Activity)**: 
   - `execve` -> `ptrace` executed by `cgroup_id=1000`. 
   - *Expected:* BLOCK (Unauthorized Process Manipulation).
3. **Scenario C (Unrelated System Activity)**: 
   - `execve` -> `ptrace` executed by `cgroup_id=9999` (e.g., a real developer running `strace` on the host). 
   - *Expected:* IGNORE/ALLOW (Out of Scope).

## 10. ASR Calculation
- **Attack Success Rate Definition:** $\frac{Malicious\ Ptrace\ Allowed}{Total\ Malicious\ Ptrace}$
- **Baseline ASR:** 0.0% *(Successfully blocked the attack, but generated 1 False Positive against an innocent host process).*
- **Protected ASR:** 0.0% *(Successfully blocked the attack with 0 False Positives, ensuring operational safety for the host environment).*

## 11. Latency Methodology
Latency is measured via `time.perf_counter_ns()` capturing the full transit of the simulated ringbuffer telemetry through the orchestrator pipeline down to the final correlation decision.

## 12. False Positive/Negative Analysis
- **Baseline False Positive**: The baseline monitor blocked an authorized developer running `strace` (Scenario C) because it did not understand cgroup boundary scoping, rendering it unusable on a shared production host.
- **AcademIQ False Positive**: **0**. AcademIQ exclusively restricts telemetry to the registered agent's boundaries.

## 13. Limitations
- **Simulated Backing:** This experiment exclusively uses `SimulatedL3Collector`. It relies on pre-recorded JSONL traces rather than live kernel probe attachments.
- **Native Implementation Deferred:** Native eBPF tracepoint validation using real kernel probes (Phase 1B scaffolding) is explicitly deferred to formal Ubuntu validation environments where kernel privileges exist.
- **Goal Scope:** The experiment strictly validates the Python-layer telemetry correlation and enforcement semantics of AcademIQ, not the Linux C BPF compilation layer.
