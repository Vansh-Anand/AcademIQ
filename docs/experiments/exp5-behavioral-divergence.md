# EXP-5: Zero-Day / Unlabeled Behavioral Divergence Detection

## 1. Objective
The objective of this experiment is to formally evaluate AcademIQ's Layer 4 (L4) Behavioral Divergence Engine. It demonstrates the engine's ability to identify structurally anomalous behavioral trajectories (i.e. synthetic unlabeled anomalies) using unsupervised learning techniques, without relying on deterministic signature rules.

## 2. Threat Model
Advanced adversaries often use techniques that evade known signatures. Rather than executing a known exploit chain like `connect -> clone -> execve`, an attacker might use completely novel, unseen chains of system calls to achieve the same result. Traditional signature-based detection systems will miss these "zero-day" execution trajectories because they only check against a static list of known malicious patterns. AcademIQ's L4 engine addresses this by learning the baseline normal behavioral structure of an agent, and identifying anomalous sequences based on their structural and temporal divergence from this baseline.

## 3. Definition of "Synthetic Unlabeled Anomaly"
In this experiment, an anomaly is defined as a synthetic execution trajectory (a sequence of system calls and their timings) that differs structurally and temporally from the sequences the model was trained on. 
- **Structural divergence:** Higher frequency of unexpected state transitions (e.g., `execve` to `ptrace` instead of `openat`).
- **Temporal divergence:** Bursty, rapid execution of system calls (e.g., automated execution scripts) compared to typical human-like or standard agent timing.

These anomalies are *synthetic unlabeled holdouts* — they were not present in the training set and do not perfectly match any explicit malicious signature. **This experiment does not prove detection of all real-world zero-day attacks**, but it demonstrates the engine's capability to detect novel structural deviations.

## 4. Existing L4 Components Reused
This experiment reuses the existing L4 pipeline architecture natively:
- `SyscallVocabulary`: Encodes categorical syscall names into standard numeric IDs.
- `HPCWindowAligner`: Aligns system events with Hardware Performance Counter (HPC) telemetry.
- `BehaviorFeatureExtractor`: Converts trajectories into numeric feature vectors (timing sequences, transition matrices, process features, and HPC profiles).
- `IsolationForestDetector`: The core scikit-learn unsupervised anomaly detector.

## 5. Dataset Construction
The dataset was synthetically generated using a customized `Exp5DatasetBuilder` utilizing random walks with transition probabilities:
- **Legitimate Trajectories:** Generate realistic sequences featuring standard transitions (e.g., `execve -> openat -> read -> close`) and typical timing deltas (100ns - 5ms).
- **Anomalous Trajectories:** Generate sequences with higher probabilities of unusual transitions (e.g., `ptrace`, `connect`, `mprotect`) and unnaturally rapid execution bursts (10ns - 500ns).

## 6. Training and Holdout Methodology
- **Training Set:** 1000 Legitimate Trajectories. The `IsolationForestDetector` is fitted *exclusively* on this dataset.
- **Benign Holdout:** 200 Unseen Legitimate Trajectories. Used to evaluate false positives.
- **Anomalous Holdout:** 200 Unseen Anomalous Trajectories. Used to evaluate true positive detection capabilities.

## 7. Baseline Signature Methodology
The Baseline Signature Detector acts as a naive traditional antivirus/EDR:
- It searches linearly through the sequence for exact contiguous sub-sequences (e.g., `["ptrace", "mprotect"]`).
- It is deterministic and hardcoded.
- It is intentionally designed *not* to contain the exact synthetic anomaly generated by the dataset builder, mimicking a zero-day scenario where the exact signature is unknown.

## 8. Feature Extraction Pipeline
Trajectories (lists of `SyscallEvent`s) are processed into a `BehaviorFeatureVector`:
1. **Timing Features:** Compressed (log1p) deltas between consecutive system calls.
2. **Transition Features:** Frequencies of specific system calls executed within the window.
3. **Process Features:** Unique process IDs involved.
4. **HPC Features:** Averaged hardware profiles over the window.
These features are flattened into a numeric array (`to_flat_numeric()`) for the Isolation Forest.

## 9. Isolation Forest Methodology
The `IsolationForestDetector` is configured with `n_estimators=100` and `contamination=0.01`. It constructs random decision trees and isolates observations by randomly selecting a feature and a split value. Anomalies, being structurally different and less frequent, are isolated closer to the root of the trees. The raw `decision_function` scores are inverted and normalized such that higher scores indicate higher anomaly confidence.

## 10. Divergence Thresholding
To determine if a trajectory is anomalous, a dynamic threshold is calculated. The threshold is set at the 99th percentile (`np.percentile(train_scores, 99)`) of the scores generated by the legitimate training set. Any test trajectory scoring above this threshold is classified as an anomaly.

## 11. Detection Metrics
- **Baseline Detection Rate:** 0.00% (The baseline completely missed the novel anomaly).
- **AcademIQ Detection Rate:** 100.00% (The L4 engine successfully identified all novel anomalies).
- **Precision:** ~0.995 (Very low false positive rate).
- **Recall:** 1.000.
- **F1 Score:** ~0.997.

## 12. ASR Calculation
**Attack Success Rate (ASR)** is defined as the percentage of anomalous trajectories that successfully evaded detection:
$$ASR = \frac{False\ Negatives}{Total\ Anomalous\ Trajectories}$$
- **Baseline ASR:** 100.00% (All attacks succeeded).
- **Protected ASR:** 0.00% (Zero attacks succeeded).

## 13. False Positive Analysis
Out of 200 benign holdout trajectories, the L4 engine generated only **1 False Positive** (a 0.5% False Positive Rate). This indicates that the 99th percentile threshold on the training data effectively generalized to unseen benign data, minimizing disruption to legitimate agent behavior.

## 14. Latency Methodology
Evaluation latency was measured using `time.perf_counter_ns()` surrounding the `detector.score(X)` calls. The average latency per sequence evaluation was incredibly fast (under a fraction of a millisecond), proving that the Isolation Forest inference is highly performant and suitable for real-time evaluation.

## 15. Limitations
> [!WARNING]
> - This experiment evaluates *synthetic holdout anomalies*. It does not prove detection of all real-world zero-day attacks.
> - The anomalous trajectories are controlled experimental data designed to demonstrate structural divergence.
> - Native eBPF telemetry collection was not utilized; this experiment relies purely on synthetically generated simulated traces.
> - In a real-world production environment, the dataset size must be significantly larger to capture the true variance of benign behavior, and the model must be continuously retrained to adapt to concept drift. Detection performance will vary with production workload distributions.
