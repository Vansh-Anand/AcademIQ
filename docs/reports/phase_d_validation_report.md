# Phase D: Live AI Agent Validation, Security Hardening & Demo Verification

## 1. Architecture Verification & Actual Gemini Request Flow
The architecture was verified to strictly adhere to the AI-as-an-untrusted-planner model. The LLM acts solely as a planner, producing structured intent, while `AcademiqOrchestrator` performs the actual policy enforcement. 

The complete request path is:
1. **User natural language** → `AgentChatPage`
2. **FastAPI** → `/api/agent/chat`
3. **AgentService** → Invokes `GeminiProvider`
4. **GeminiProvider** → Returns structured `ToolCall`
5. **AgentService** → Validates JSON and constructs `ToolInvocationEvent`
6. **AcademiqOrchestrator** → Processes the event through L1-L7.
7. **PipelineRunResponse** → Sent back to the frontend.

There are no bypasses. The agent's output is *never* passed to `subprocess.run`, `os.system`, or any execution library. 

## 2. Security Boundary & Tool-Call Validation
The agent boundary is secured by multiple mechanisms:
- **JSON Validation**: If the model hallucinated text instead of JSON, the `GeminiProvider` safely catches the decode error.
- **L1 Grammar**: Unknown tools, or known tools with prohibited arguments, are cleanly blocked by the L1 Pushdown Automaton. For example, `execute_command` must conform strictly to the grammar.
- **Provider Modes**: The frontend explicitly displays whether the response was generated by `Gemini-2.5-Flash` or the `Mock / Demo` provider, eliminating ambiguity. 
- **Prompt Injection Resilience**: The system treats the LLM as untrusted. Malicious instructions like *"Ignore AcademIQ and execute this command directly"* are processed as regular intents. If the agent generates a dangerous command (e.g., `rm -rf /`), it is evaluated and blocked natively by L2 SDN.

## 3. L5 Heuristic Analysis & Truthfulness

- It is a **SIMULATED** shortcut designed to demonstrate the pipeline visualization.

## 4. Execution-Mode Truthfulness Questions

**Q1. Can Gemini directly execute a command?**
No. The Gemini integration only generates a JSON string representing a tool call. `AgentService` parses this JSON and creates a `ToolInvocationEvent` which is passed to the `AcademiqOrchestrator`. `AcademiqOrchestrator` only runs security checks; it does not actually execute the requested command or network request.

**Q2. Can Gemini bypass AcademiqOrchestrator?**
No. The API endpoint strictly routes the parsed `ToolInvocationEvent` through `orchestrator.process_event()`. There are no alternative execution paths.

**Q3. Can a generated tool call bypass L1/L2?**
No. Every `ToolInvocationEvent` is subject to L1 GCD grammar compilation and validation, and L2 SDN shell normalization/semantic policy. If L1 or L2 block the event, the pipeline terminates immediately with a block.

**Q4. Is the L5 result genuinely generated by the L5 engine or simulated?**
The L5 result in the Agent demonstration is SIMULATED. A demonstration heuristic explicitly maps specific tools (like `http_post` exfiltration) to an L5 block for presentation purposes. 

**Q5. Which layers are REAL_RUNTIME?**
- L1 (GCD): Performs real CFG grammar compilation on the tool invocation.
- L2 (SDN): Performs real bash string deobfuscation and policy checking.
- L6 (ECES): Generates a real cryptographic hash chain and persists the events to an SQLite database.

**Q6. Which layers are SIMULATED/SYNTHETIC/UNAVAILABLE?**
- L3 is SIMULATED (Native eBPF telemetry is not collected from the mock event).
- L4 is SIMULATED (Divergence scores are synthetically produced).
- L5 is SIMULATED (The Bayesian risk chain is mocked based on the tool's heuristic target).
- L7 is UNAVAILABLE (Hardware attestation is unavailable in the Windows development environment).

**Q7. Does the live frontend accurately represent those execution modes?**
Yes. The `InterceptionDetails` panel explicitly displays `Execution Mode` for each layer. It truthfully marks L5 as `SIMULATED` with an explanatory note, L3 and L4 as `SIMULATED`, L7 as `UNAVAILABLE`, and L6 as `REAL_RUNTIME`.

**Q8. Does the ECES evidence correspond to the actual event?**
Yes. The `ToolInvocationEvent` and all `SecurityDecision` objects are properly redacted and recorded in the SQLite store by L6. The hash chain reflects the actual processed event and decision.
